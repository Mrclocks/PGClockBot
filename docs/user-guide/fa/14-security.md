# امنیت و Security Center

## هدف

Security Center وضعیت هویت و credentialهای حساس را برای نقش‌های مربوط نمایش می‌دهد.

## اصل Fail-Closed

اگر هویت، credential یا Scope قابل اعتماد نباشد، دسترسی باید رد شود. نباید از Owner credential یا Platform scope به‌عنوان fallback استفاده شود.

## Web Password و PG Password

رمز ورود Web و رمز اتصال PasarGuard دو مفهوم متفاوت‌اند، مگر اینکه عمداً همگام‌سازی شوند. تغییر یکی را نباید بدون بررسی رفتار سیستم معادل تغییر دیگری دانست.

## Brute Force

ورود Web دارای محدودسازی تلاش‌های ناموفق است. محاسبه Client IP نیز برای جلوگیری از سوءاستفاده از X-Forwarded-For به تنظیم trust proxy وابسته است.

## Session

Session وب زمان انقضا دارد و مجوزهای حساس نباید صرفاً بر داده‌های قدیمی داخل Session متکی باشند؛ ACLهای حساس باید تا حد ممکن از وضعیت زنده یا Guard مناسب تبعیت کنند.

## Scope

مالکیت منابع، Tenant و PG Scope باید در Backend بررسی شوند.

## مثال

اگر یک حساب قبلاً مجوزی داشته و بعداً Role آن کاهش یافته باشد، UI یا Session قدیمی نباید باعث ادامه دسترسی حساس شود.

## توصیه

هر تغییری در Owner، PG Admin، credential، ACL یا Scope باید با احتیاط و همراه با بررسی سلامت سیستم انجام شود.
