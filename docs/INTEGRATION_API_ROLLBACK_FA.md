# برگشت امن از Integration API

خاموش‌کردن API، ساخت یا تمدیدی را که قبلاً به پاسارگارد ارسال شده برنمی‌گرداند.
این راهنما برای توقف کار جدید و انتخاب نسخهٔ سازگار است؛ `alembic downgrade`
به‌تنهایی برنامه، workerها یا درخواست در حال اجرای پنل را متوقف نمی‌کند.

## اگر integration هرگز فعال نشده است

روش زیر فقط برای نسخهٔ پیش از قابلیتِ بررسی‌شده‌ای است که head مایگریشن آن
`0070_shop_miniapp_key` است. نسخه‌ای با head قدیمی‌تر به مسیر مایگریشن جداگانه
و بررسی‌شده نیاز دارد؛ رسیدن به ۰۰۷۰ سازگاری با هر نسخهٔ قدیمی را تضمین نمی‌کند.

1. پردازش ربات و همهٔ workerها را متوقف کنید و از دیتابیس، پوشهٔ `data` و تنظیمات
   نسخهٔ فعلی بکاپ بگیرید. فایل بکاپ و کلید `WEB_SECRET` را محرمانه نگه دارید.
2. بررسی کنید هیچ سرویس وب‌سایتی، عملیات ارسال‌شده یا نتیجهٔ نامعلوم وجود ندارد.
   صرفاً خاموش‌بودن فلگ‌ها اثبات این موضوع نیست.
3. پیش از جایگزین‌کردن کد، با محیط و کد همین نسخه، ابتدا روی کپی بکاپ دستور
   `alembic downgrade 0070_shop_miniapp_key` را اجرا کنید. این دستور شمارهٔ
   مایگریشن را برای نسخهٔ پیش از قابلیت آماده می‌کند؛ مالکیت مشتری و جدول‌های
   دارای وابستگی نگه داشته می‌شوند. نصب مستقیم نسخهٔ قدیمی روی دیتابیسِ ۰۰۸۰
   با خطای `Can't locate revision` متوقف می‌شود.
4. نسخهٔ قبلی را با همان کپی دیتابیس و تنظیمات نگهداری‌شده امتحان کنید. فلگ‌های
   زیر را خاموش بگذارید و ستون‌ها و جدول‌های افزوده را دستی حذف نکنید. بالا آمدن
   برنامه، نمایش کاربران و سرویس‌های قبلی و ثبت یک سرویس تلگرامی جدید را بررسی کنید.
5. پس از موفقیت آزمون کپی، آماده‌سازی مایگریشن و جایگزینی نسخه را روی دیتابیس
   اصلیِ متوقف‌شده تکرار کنید؛ سپس برنامه را راه‌اندازی کنید.

## اگر integration فعال شده یا درخواست به پنل ارسال شده است

1. ارسال درخواست جدید از وب‌سایت را متوقف کنید. فلگ‌های
   `INTEGRATION_API_ROUTES_ENABLED`، `INTEGRATION_EXECUTION_ENABLED` و
   `INTEGRATION_WEBHOOKS_ENABLED` را `false` و تنظیم سراسری
   `integration_api_enabled` را `0` کنید؛ سپس همهٔ پردازش‌ها و workerها را متوقف کنید.
2. پس از توقف، بکاپ کامل بگیرید. شناسه‌های مشتری، targetهای ذخیره‌شده، عملیات،
   کلیدهای تکرار درخواست، guardها، رزرو ظرفیت، رضایت اتصال تلگرام، outbox و
   کلیدهای رمزگذاری و امضا و نشانگر داخلی `integration_execution_started` باید حفظ شوند.
   این نشانگر، رزرو ظرفیتِ نتیجه‌های نامعلوم را حتی پس از خاموش‌کردن اجرا نگه می‌دارد.
3. درخواست‌های ارسال‌شده و نتیجه‌های نامعلوم را با خواندن همان هدف ذخیره‌شده
   بررسی کنید. انقضای lease مجوز تکرار درخواست، آزادکردن ظرفیت یا بازپرداخت نیست.
4. برای ادامهٔ کار، یک نسخهٔ قبلیِ بررسی‌شده که **مالکیت مشتری و سرویس‌های بدون
   `bot_user_id` را پشتیبانی می‌کند** نصب کنید. نسخهٔ پیش از این قابلیت قابل استفاده
   نیست و دستور بازگشت به ۰۰۷۰ در بخش قبل برای این حالت مجاز نیست. پیش از
   جایگزینی کد، با کد فعلی و روی کپی بکاپ، شمارهٔ مایگریشن را به head واقعی همان
   نسخهٔ سازگار برسانید. تا تعیین تکلیف سرویس‌های وب‌سایتی، عملیات بومی پنل روی آن‌ها انجام ندهید؛
   با خاموش‌بودن فلگ‌ها، fencing اختیاری مسیر بومی فعال نیست.
5. قبل از راه‌اندازی، نسخهٔ انتخابی را روی کپی بکاپ امتحان کنید. پس از تغییر مستقیم
   تنظیم دیتابیس، همهٔ پردازش‌ها باید دوباره راه‌اندازی شوند. فعال‌سازی مجدد را جدا
   از rollback و پس از بررسی عملیات نامعلوم انجام دهید.

اگر بازگشت به نسخهٔ پیش از قابلیت ضروری است، بازیابی کامل بکاپِ قبل از فعال‌سازی
به‌همراه همان تنظیمات و کلیدها لازم است. تغییرات بعد از بکاپ و اثرهای ایجادشده در
پاسارگارد باید ابتدا تطبیق داده شوند؛ برگرداندن فقط دیتابیس، اثر پنل را حذف نمی‌کند.
این مسیر جایگزین فوری یا خودکار برای نسخهٔ سازگار نیست.

تست لوکال بکاپ، آزمون واقعی ساخت و تمدید روی پنل آزمایشی را جایگزین نمی‌کند.
